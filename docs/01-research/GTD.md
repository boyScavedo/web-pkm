# GTD (Getting Things Done)

## Overview

David Allen's methodology for capturing, clarifying, and organizing commitments.

## Core workflow

1. **Capture**: Everything that has your attention goes into inbox
2. **Clarify**: Is it actionable? What's the next action? Is it a project?
3. **Organize**: Sort into lists — next actions, waiting for, projects, someday/maybe
4. **Reflect**: Regular review (weekly review is the keystone habit)
5. **Engage**: Do the work based on context, energy, time, priority

## What we take from GTD

- **Inbox as first-class concept** — low-friction capture, process later
- **Next actions** — tasks tied to projects or standalone
- **Weekly review** — a built-in review mechanism
- **Clarification step** — inbox items need processing, not immediate filing

## What we skip

- Elaborate context/@-tags system (overkill for single user)
- Complex waiting-for tracking (use task notes instead)
- Physical reference filing (irrelevant for digital PKM)

## Implementation

- `status: inbox` on notes for GTD capture
- Tasks as a separate entity linked to notes/projects
- Weekly review dashboard (Phase 09)
- Quick capture API for fast input (Phase 03)
